### Capacity claim: a stronger source and an important negative result

The new [**2026-11-13 thousand-concurrent-agents plan**](https://github.com/paperclipai/paperclip/blob/a665ed6a1b990a96f11f73ea7bd73a8228e511e9/doc/plans/2026-11-13-thousand-concurrent-agents.md) is valuable **competitor counterevidence** for `criterion:C1`, `criterion:C4`, `criterion:C5`. It includes an upstream-maintainer load model that runs real event append, checkpoint, lease and authentication code against local PostgreSQL with **simulated agents**. Following Phase 1 optimizations, the author reports that the *recorded-rate model* processed an offered workload of 1,000 simulated agents with 30,000/30,000 non-delta events in 60 seconds, event-loop utilization 0.61 and p99 non-delta lateness 10 ms; it also reports 2,000 simulated agents with p99 about 2.1 s and utilization 0.85. These are **maintainer-reported component measurements**, not independently reproduced results or 1,000 real concurrent model-using agents.

The author also derived recorded-rate assumptions from **40 actual hosted native runs** (median duration 26 minutes), rather than using a 20-delta/s stress stream for every run. This gives a more representative hypothesis, but the sample is not a 1,000-run fleet. The report acknowledges shared machine load, missing retained raw output for an earlier baseline, and that asynchronous checkpoint saves in the model understate backpressure to the real runner. The stated target is a one-hour, 1,000-*real-agent* campaign over multiple processes, with no Retry and explicit resource/latency thresholds. The same plan says Phase 2 multi-controller work is **not started**; the first real-agent ramp attempt on **2026-11-15** did **not launch any runs** because the environment needed a managed AI connection. It is not a pass/fail for the 1,000-agent target. Do not infer a product throughput score or fleet superiority from either result.

Keep Paperclip's strengths in view: transactional native receipts, source deduplication and conflict checks, bounded delivery, recovery fencing, source-level optimizations, and the new detailed ramp/runbook. The new evidence weakens prior generalized claims of Paperclip's unavoidable event-ingestion ceiling, while leaving full hosted active-fleet qualification unknown.
