# Initial technical assessment: source evidence and conditional target behavior

Date: 2026-11-03. Status: initial advisory assessment, unranked. No competitor tests or capacity campaigns were run. Scores are ordinal engineering judgments under the shared methodology, not measurements, probabilities, security certifications or production-readiness verdicts. The historical 7.6/8.3 totals remain in the [original-rubric record](../studies/initial-paperclip-comparison.md) and are not copied into this rubric.

## Fixed scope and reading rules

**Global matrix mask:** E1–E5, C1–C5, S1–S5, D1–D5, M1–M5, P1–P5, all applicable to the whole-product `product-v1` scenario. Its promise includes SaaS, standalone self-hosted and Fully Local, with multi-user/multi-organization server operation and an eventual thousands-active-agent envelope. No edition borrows another edition's capabilities. No unreviewed cell is zero; `unknown` means `score: null`.

**Paperclip subject:** the open-source self-hosted product and bundled runner/plugins represented by commit `61e8d5c7eb097664958e00c30ccd88bb51359043`. This is a targeted source assessment of present implementation. Source documents support only their stated capability claims. Hosted commercial service behavior is not borrowed into this subject. D1 is unknown because the reviewed open-source subject does not establish its actual managed offering; this is not a claim that no managed edition exists.

**Agent Teams subject:** prospective behavior of the selected Runtime, Orchestrator and Platform plans at the pinned snapshots below, **assuming they are correctly implemented**. Open decisions remain open. This is not a score of current implementation or document polish. The qualifier applies to every target cell, including those rated 9; those ratings do not assert implementation, release or deployment qualification. Undecided provider/IAM/aggregate/accounting choices are not invented to fill gaps.

Each numeric cell is `point [plausible range], confidence /10`. Confidence uses the disclosed ordinal mapping high = 9/10, medium = 6/10, low = 3/10; these are not probabilities. Ranges are reviewer judgments, not statistical intervals. The point generally uses the common 0/3/5/7/9/10 anchors. Confidence and missing evidence are shown independently from quality. A high score on an inspected native path can coexist with medium confidence about product-wide coverage. A scoped positive finding does not fill a whole-product criterion when material parts of that criterion remain unreviewed or unselected.

This **mixed-basis matrix has no total, winner or ordinal rank**. A separate conditional architecture view follows, with the same assumption on both sides. The fixed criterion mask prevents favorable per-row selection. Coverage here is simply the fraction of rated criteria under this 30-cell mask; equal dimension sizes make this identical to the default weighted coverage. It measures review completeness, not product quality.

### Why a new single overall potential score is not defensible yet

There is enough evidence for the scoped judgments above. There is not enough to assign one new whole-product number without hiding important open branches: OD-004 runtime capabilities, OD-006 aggregates/concurrency, OD-012 identity/authorization/isolation, OD-024 exact consumption semantics, and the separately owned capacity/profile qualification work [N-A4–N-A7]. Correct implementation of selected plans does not resolve an unselected branch. Static architecture comparison does **not** require a load test; a claim about thousands of simultaneously active agents does. Both C1 capacity cells therefore remain unknown.

The old **Paperclip 7.6 / Agent Teams target 8.3** stays historical under its original rubric and assumptions. It is neither a current implementation result nor the aggregate of these named lenses. Recomputing a new 8.x number from partially overlapping criteria would create precision without additional evidence.
